- Tooltip situation — **fully reworked and unified, all live-verified**:
  - Two tooltips fighting for visibility, randomly one or the other showing — root cause was the whole two-tooltip architecture (a custom `region-tooltip` div racing ECharts' own built-in one via mouseover/mouseout JS). Fixed by removing the split entirely: there is now exactly one tooltip again, driven purely by hovered x-position (axis-trigger), so there's nothing left to race.
  - The axis-slice was snapping to whichever recorded point was nearest in raw time, which is wrong for a step-line chart across a data gap — the value at any moment is whatever the *previous* point held, not whichever point (before or after) happens to be closer. `axisTooltipHtml` now ignores ECharts' own per-series nearest-point snapping and independently looks up the correct held point (and the correct linearly-interpolated projected value once past the last real sample) from each series' own data, given only the shared hovered timestamp (ECharts' `axisValue`).
