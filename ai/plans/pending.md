  - This means the banner is a GrowthBook feature-flag value, not a stable per-purpose API — the numeric feature-flag key (`19186470`) is an internal id that could change across GrowthBook config edits, and the endpoint requires an authenticated web session (not CLI-accessible). Checked whether the key could be recovered/verified instead of hardcoded: the `statsig_hashing_algorithm` query param picks the hash function applied to the (still-hidden) real flag name server-side (`djb2` → the short numeric key seen above; anything else, including an unrecognized value, falls back to a default that turns out to be SHA-256-base64, e.g. `Gidz4JDhcW4tRXx9U91WCq1OzW1CBaXm2CSmkNKnTC4=`) — neither reveals the plaintext name, so there's no way to derive/verify the key other than by its distinctive `defaultValue` content.
